This release lets agents attach their own data to a PR and lets a project set the layout of PR bodies. PR bodies now have brief sections. It also fixes a `pr land` that could poll forever on green CI, and several merge-gate edge cases in `ci wait`.

## Upgrade

Binary install: run the one-liner again; it replaces `~/.local/bin/ghx` in place.

```sh
curl -fsSL https://github.com/thegoldenmule/gh-for-agents/releases/latest/download/install.sh | sh
ghx install   # refreshes the CLAUDE.md block (it now mentions data)
```

npm install: `npm i -g https://github.com/thegoldenmule/gh-for-agents/releases/latest/download/ghx.tgz`, then `ghx install`.

**Upgrade every machine that edits your PRs.** v0.1.0 doesn't know the new body layout:

- its `pr status` reports `description` drift on PRs created by v0.2.0;
- its `pr edit` drops `data` and writes the old layout back.

## PR bodies have sections

The built-in layouts now have short sections:

- **Summary:** the description and the trailer line.
- **How to test:** only with `render.mode: "details"`.
- **Data:** only when the PR has data.

A section with nothing to show is left out. The description is still 1–3 plain sentences.

- New PRs get the new layout.
- An existing PR keeps its body until its next `pr edit`. That edit re-renders it and warns `TEMPLATE_CHANGED`.
- The hidden block now records `layout`, a hash of the template that rendered the body.
- `pr status` `description.drift` reports `layout` when the template has changed since.

## Agent data: `data`

`pr create` and `pr edit` take an optional `data` object of extra facts, such as `{"ticket": "ENG-12", "rollout": "canary"}`.

- **Limits:** up to 20 keys and 2 KB. A value is a one-line string (up to 300 chars), a number, a boolean, a list of those, or an object one level deep.
- **In the body:** data is listed under Data. Values are shown as inline code, so a value can't @mention anyone or close an issue.
- **Read back:** `pr status` returns it as `meta.data`, so another agent can read it with `--fields meta.data.ticket`.
- **Trust:** if the PR's author isn't trusted (`trust.associations`), `meta.data` is `{}` and `pr status` warns `UNTRUSTED_DATA`.
- **Editing:** `pr edit` merges `data` by key. `{"k": null}` deletes one key, and `"data": null` deletes all of them.
- **Credentials:** values that look like credentials (`ghp_…`, `github_pat_…`, `AKIA…`, private keys) are refused as `data.secret_like`.

A project can declare fields in `.github/ghx.json`:

```json
"data": {
  "fields": {
    "ticket": { "type": "string", "pattern": "^ENG-\\d+$", "required": true, "example": "ENG-1" },
    "rollout": { "type": "enum", "values": ["flag", "canary", "full"], "requiredFromRisk": "medium" }
  }
}
```

- **Types:** `string`, `enum`, `number`, `boolean`, `string[]`.
- **Required:** a declared field is required either always, or from a given risk up.
- **Extra keys:** an agent can add any keys beyond the declared ones, but can't leave out a required field (`data.required`, with a did-you-mean for a likely typo).
- **Example:** `--example` includes the required fields.

## Project templates: `render.prBody`

A project can replace the built-in layout with its own template, as a string or a list of lines:

```json
"render": {
  "prBody": ["## Why", "", "{{description}}", "", "Ticket: {{data.ticket}}", "", "{{trailer}}", "", "## Facts", "", "{{data}}"]
}
```

- **Placeholders:**
  - Each alone in its paragraph: `{{description}}`, `{{trailer}}` (both required), `{{howToTest}}` and `{{data}}`.
  - Anywhere in a paragraph: `{{risk}}`, `{{revertPolicy}}`, `{{components}}`, `{{testSummary}}`, `{{riskNote}}`, `{{revertNote}}`, and `{{data.<key>}}` for a declared key.
- **Empty parts:** a section whose placeholders are all empty is left out, heading included.
- **Footer and block:** ghx appends the footer and the hidden block after the template. A template can't move or remove either.
- **Validation:** templates are checked when the config loads. Problems are `CONFIG_INVALID` with `render.prBody.*` codes and did-you-mean hints, so `ghx doctor` reports them.
- **Preview:** use `--dry-run` to see the rendered body.

## Fixes

- **`pr land`:** it can no longer poll forever on green CI. The merge-gate bound now lasts across `--foreground` re-runs, and a `ci rerun` resets it. Gate checks that never start now stall with reason `gate-stalled`.
- **Required checks:** a bound expected set still includes the repo's required checks, so `pr land` can't merge without one that was added after the wait started.
- **Config changes during a wait:** a `ci wait` that follows another one re-derives its answer when the config has changed (`WAIT_CONFIG_CHANGED`). `pr land` merges against the checks its gate judged.
- **`CONFIG_DRIFT`:**
  - It warns when the working tree's `.github/ghx.json` is behind the base branch's.
  - It only fires when the base changed the config after your branch forked.
  - `CI_PENDING` names where `ci.expected` was read.
- **`pr merge`:** it reports the head branch's state as `headBranch {state, deletedBy, autoDelete}`, including when GitHub deleted the branch itself.
